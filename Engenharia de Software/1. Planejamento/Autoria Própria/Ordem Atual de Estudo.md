# Ordem Atual de Estudo

- “Planejamento” ==não é exatamente uma etapa== do SDLC; é uma atividade transversal que organiza o projeto antes e durante as etapas do ciclo de vida.

Ou seja, apesar de separarmos e organizarmos desta maneira, busque durante seus estudos entender que não necessariamente isto é feito somente antes das demais.

Na verdade, todo o SDLC não costuma geralmetne ser sequencial e linear. Ao menos, não em todas metodologias (não é mesmo, senhor cascata?...).

## SWEBOK
Aqui eu faria uma leitura ==menos linear e mais conceitual==.

O núcleo é:
*SWEBOK → Software Engineering Management → Software Project Planning*

Preste atenção especialmente em:
- seleção do **SDLC model**;
- adaptação do processo;
- escopo;
- requisitos;
- riscos;
- qualidade;
- recursos;
- estimativas;
- cronograma;
- responsabilidades;
- acompanhamento e revisão do plano.

Isso é particularmente interessante para a sua metodologia porque o próprio SWEBOK conecta explicitamente o planejamento à *seleção do modelo de ciclo de vida* e à sua adaptação conforme escopo, requisitos e riscos.

## Sommerville
Use Sommerville para ==ampliar sua visão==, *Chapter 23 — Project Planning*.

Ele é ótimo porque coloca juntos:
- project planning;
- software costing;
- project scheduling;
- cost estimation;
- plan-driven planning;
- agile planning;
- COCOMO II.

A própria descrição do capítulo lista esses objetivos.
Isso faz dele uma boa segunda perspectiva depois do Pressman.

E há uma diferença interessante entre os dois autores:
- **Pressman** tende a te dar uma visão bastante estruturada das atividades de planejamento.
- **Sommerville** ajuda a perceber que planejamento depende muito do **contexto do processo de desenvolvimento**.
